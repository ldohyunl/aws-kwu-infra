[VPC 만들기 : 일반적인 절차]
<이론>
- VPC 만들기 : IP Range 결정 시 고려 사항 
- VPC 만들기 : Subnet 생성 시 고려 사항   
 > 가용 IP : 251개
 > 예약된 IP 주소가 있음. (Subnet CIDR이 10.0.0.0/24 인 경우) 0번, 1번, 2번, 3번은 못쓰고, 4번부터 가용
	10.0.0.0 : 네트워크 주소
	10.0.0.1 : VPC 라우터용으로 예약된 주소
	10.0.0.2 : AWS에서 예약된 DNS 주소, AmazonProvidedDNS
	10.0.0.3 : AWS에서 향후 사용을 위하여 예약
	10.0.0.255 : 브로드캐스트 주소, VPC에서는 브로드캐스트를 지원하지 않으며, AWS에서 예약.

- VPC 만들기 : Routing  
- VPC 만들고, 서버, 라우팅 등등을 넣어줘야 한다. 
 > 통으로 하나 만들고, 서브넷으로 나눠준다. 

<진행>
01. VPC 생성
    이름태그 : KWU-PRD-VPC
	IPv4 CIDR 블록 : 10.250.0.0/16  (65,563),
		IPv6 CIDR 블록 -> IPv6 CIDR 블록 없음
	VPC생성 선택. 
	

02-1. Public Subnet 생성
    1) AZ : 2A
     KWU-PRD-VPC-NGINX-PUB-2A      (10.250.1.0/24) - 251   
	 KWU-PRD-VPC-BASTION-PUB-2A    (10.250.4.0/24) - 251
	 
    2) AZ : 2C
	 2중화 구성 작업 때 사용
	 KWU-PRD-VPC-NGINX-PUB-2C      (10.250.11.0/24) - 251
	 > 서브넷 이름은 KWU-PRD-VPC-NGINX-PUB-2C  로 입력
	   가용영역은 ‘아시아 태평양(서울) / ap-northeast-2c’로 지정
	   IPv4 서브넷 CIDR 블록은 ‘10.250.11.0/24’로 입력 후 [서브넷 생성] 클릭

02-2. 이번에는 Private 영역의 서브넷 2개 생성, [서브넷 생성] 버튼 클릭 
    1) AZ : 2A 
     KWU-PRD-VPC-TOMCAT-PRI-2A      (10.250.2.0/24) - 251   
	 > VPC ID는 생성한 ‘KWU-PRD-VPC’로 연결
	 > 서브넷 이름은 ‘KWU-PRD-VPC-TOMCAT-PRI-2A’로 입력
	   가용영역은 ‘아시아 태평양(서울) / ap-northeast-2a’로 지정
	   IPv4 서브넷 CIDR 블록은 ‘10.250.2.0/24’로 입력 후 [서브넷 생성] 클릭
	2) AZ : 2C
     > 서브넷 이름은 ‘KWU-PRD-VPC-TOMCAT-PRI-2C’로 입력
	 > 가용영역은 ‘아시아 태평양(서울) / ap-northeast-2c’로 지정
	 > IPv4 서브넷 CIDR 블록은 ‘10.250.12.0/24’로 입력 후 [서브넷 생성] 클릭
	   
	 
03. 인터넷 게이트웨이 설치
[VPC] - [인터넷 게이트웨이] - [인터넷 게이트웨이 생성] 클릭
 > Internet Gateway 생성  : KWU-PRD-VPC-IGW
   > Pub Sunbet 에 있는 인스턴스가 인터넷을 사용할 수 있도록 해주기 위함    
 > 인터넷 게이트웨이가 생성되면 다음과 같이 상태가 ‘Detached’로 나타남. 
   이는 해당 인터넷 게이트웨이가 VPC와 연결되어있지 않기 때문이므로
   [작업] - [VPC에 연결]을 클릭
 > 인터넷 게이트웨이 igw-081ffa943d78f555c이(가) vpc-0caf2973cfca7428a에 연결되었습니다.
 > 내가 만든 ' KWU-PRD-VPC' 와 연결된 IGW 상태가 ‘Attached’로 변경된 것을 확인  



04. NAT 게이트웨이 설치  
[VPC] - [NAT 게이트웨이] - [NAT 게이트웨이 생성] 클릭
(05. NAT GATEWAY  생성)
 > Private Subnet에 있는 인스턴스가 인터넷을 사용할 수 있도록 해주기 위함
 > 퍼블릭 존에 만들어야 함. 그래서 2A, 2C 에 만들어야 함. 
 
    KWU-PRD-VPC-NGW-2A   -- 우리 실습환경 에선 1개만 설치  (실무에서도 사용비용땜시 1개만 사용)
	  >> 서브넷은 ‘KWU-PRD-VPC-NGINX-PUB-2A’로 지정
      >> 연결 유형은 ’퍼블릭’으로 지정 >>> PUB에 만들어야 함. 
	  >> 가용성 모드 : 리전 내 모든 영역에 배포하거나 단일 가용 영역으로 제한할지 여부를 선택합니다. : 리전별 - 신규
      >> (연결 유형 NAT 게이트웨이에 대한 연결 유형을 선택합니다. 퍼블릭 V / 프라이빗 X)
	  
    KWU-PRD-VPC-NGW-2C   -- 이중화를 위해 구성하는것을 권고함.
	
 > 현재 탄력적 IP가 생성되어있지 않으므로 [탄력적 IP 할당] 클릭	(무조건 해야함)
 > 탄력적 IP 할당 를 누르면, '자동으로' NAT 게이트웨이에 탄력적 IP 주소를 할당합니다.
   >> EC2 - 네트워크 및 보안 - 탄력적 IP - 에도 생겨서 확인가능함. 같은 내용임.
 > VPC 에서 하거나, EC2 가서 'NAT 게이트웨이 설치' 하면서 생기는 탄력적 IP 주소 에 'Name'을 임의로 입력하기 
   >> 바로 안생기고, 최대 3~5분 정도 걸림. 
   >> NAT GATEWAY (안헷갈리게)
 > NAT 게이트웨이 상태 가 아직 Pending 으로 확인됨. 좀 지나서 Available(활성화) 으로 변경됨. 
 
 
 
05. 라우팅 테이블 설정
먼저 Public 영역의 라우팅 테이블 생성 
[VPC] - [라우팅 테이블] - [라우팅 테이블 생성] 클릭

5-1. Routing 테이블 생성
    KWU-PRD-VPC-RT-PUB <== PUB구간에 하나만 만들고, 아래 2개 PUB 서브넷을 포함
	> KWU-PRD-VPC-RT-PUB-2A   ,  KWU-PRD-VPC-RT-PUB-2C

	KWU-PRD-VPC-RT-PRI <== PRI구간에 하나만 만들고, 아래 2개 PRI 서브넷을 포함 
	> KWU-PRD-VPC-RT-PRI-2A   , 	KWU-PRD-VPC-RT-PRI-2C
	
5-2. Routing 테이블 편집, 연결
 - KWU-PRD-VPC-RT-PUB
   > 선택 > 오위 작업 에서 '라우팅 편집' 선택 또는 '라우팅' 탭 선택 - 라우팅 편집 , 
      > 라우팅 추가 - 0.0.0.0/0 선택 입력 - 인터넷게이트웨이 (IGW) 선택, 선택 
   > 서브넷 ID 연결
      > PUB 2A, PUB 2C 명시적 선택 연결. 
        (subnet-0180d8b12419fef91 / KWU-PRD-VPC-NGINX-PUB-2C 
          subnet-08023e16d5f9f24b2 / KWU-PRD-VPC-NGINX-PUB-2A    )

 - KWU-PRD-VPC-RT-PRI
   > 선택 - 라우팅 - 라우팅 편집
      > 라우팅 추가 - 0.0.0.0/0 선택 입력 - NAT 게이트웨이 선택, 선택 (PRI 존 인터넷 통신 역할) 
   > 서브넷 ID 연결
      > PRI 2A, PRI 2C 명시적 선택 연결. 
         (subnet-0ca8ca043c5980f99 / KWU-PRD-VPC-TOMCAT-PRI-2A 
           subnet-0e3702c97ecb66d4e / KWU-PRD-VPC-TOMCAT-PRI-2C  )

* 추후 DB는 PRI 서브넷에, BASTION은 PUB 서브넷에 추가시켜줘야 함.
