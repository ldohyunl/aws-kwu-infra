6. Nginx 설치   <== nginx2a, nginx2c 각각 해줘야 함. 
📌 Nginx 설치 가능한 버전 확인
 > apt info nginx 명령어로 name이 포함된 설치 가능한 패키지 목록을 조회한다.
 
#1번작업 - 저장소 파일 생성 및 내용 넣기
[root@ip-10-250-1-240]$ sudo vi /etc/apt/sources.list.d/nginx.list

 > 아래 코드 내용 복사하여 넣기 (Bastion-server 경유해서 접속한 Nginx2A, Nginx2C에 동시에)
 deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] https://nginx.org/packages/ubuntu jammy nginx
 deb-src [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg]  https://nginx.org/packages/ubuntu jammy nginx
 
#2번작업 - GPG 키 추가
[root@ip-10-250-1-240]$ sudo curl -fsSL https://nginx.org/keys/nginx_signing.key | sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg

#3번작업 - 저장소 업데이트 및 설치** 

[root@ip-10-250-1-240]$ sudo apt -y update
[root@ip-10-250-1-240]$ sudo apt -y install nginx net-tools

또는 $ sudo apt -y update && sudo apt -y install nginx net-tools

#4번작업 - 설치 버전확인 및 시작**

[root@ip-10-250-1-240]$ nginx -v
nginx version: nginx/1.28.0

[root@ip-10-250-11-240]$sudo systemctl start nginx
[root@ip-10-250-11-240]$sudo systemctl status nginx

root@ip-10-250-1-240:~# sudo ps -ef | grep nginx

8. Nginx EC2 와 Nginx EC2 간의 연결 
서로 아래 명령어로 실행하면 변경한 html 정보를 확인할 수 있음 → 두 인스턴스는 80포트에 대한 인바운드 보안 정책 허용을 하였기 때문!

  curl 10.250.11.240
  Nginx-2A에서 실행
  
  curl 10.250.1.240
  Nginx-2C에서 실행
  
  curl localhost:80

그러나 Ping 테스트를 진행하면 서로 연결이 되지 않음!
→ 두 인스턴스는 ICMP 연결에 대한 인바운드 보안 정책을 허용하지 않았기 때문! (안했다면..)

ping 10.250.11.240
Nginx-2A에서 실행

ping 10.250.1.240
Nginx-2C에서 실행

AWS 콘솔로 돌아가서
[EC2] - [보안그룹]에서 [인바운드 규칙]에서 [인바운드 규칙 편집] 클릭

[규칙 추가] 클릭 후 아래 표대로 추가한 다음 [규칙 저장] 클릭
모든 ICMP - IPv4  , Anywhere IPv4  , 0.0.0.0/0

VEC-PRD-VPC-NGINX-PUB-SG-2A에서 한 것처럼 VEC-PRD-VPC-NGINX-PUB-SG-2C에서도 동일하게 진행 

[EC2] - [보안그룹]에서 [인바운드 규칙]에서 [인바운드 규칙 편집] 클릭 

[규칙 추가] 클릭 후 아래 표대로 추가한 다음 [규칙 저장] 클릭
모든 ICMP - IPv4  , Anywhere IPv4  , 0.0.0.0/0
